# TANEM — обязательный маршрут публикации

Этот файл определяет единый порядок работы ChatGPT технического специалиста для каждого нового клиентского сайта.

## Что должно быть до начала

Обязательно:
- ссылка на клиентский GitHub-репозиторий;
- ссылка на карточку бизнеса/мастера;
- в репозитории уже лежат `business.json` и фотографии.

Если ссылка на репозиторий не дана — сначала запросить её. Не вносить изменения в неизвестный репозиторий.
Не просить повторно данные, которые уже есть в `business.json`, фотографиях или переданной карточке.

Желаемый поддомен можно дать сразу или перед production-публикацией. Формат: `slug.tanem.ru`, например `monroe.tanem.ru`. ChatGPT не должен сам окончательно назначать клиенту другой адрес без прямого указания пользователя.

## Обязательный порядок

1. Проверить репозиторий и определить, подходит ли выбранный шаблон: Salon или Master.
2. Прочитать `business.json`, фотографии и переданную карточку.
3. Собрать сайт строго по правилам текущего шаблона.
4. Запустить все обязательные проверки.
5. Только после зелёных проверок внести изменения в `main`.
6. Проверить фактическую публикацию GitHub Pages.
7. Вернуть реальную Pages-ссылку только после успешной публикации.
8. Если задан production-поддомен, проверить его формат и передать его только в утверждённый автоматический production-deploy.
9. Проверить, что production-сайт реально открывается по HTTPS.
10. Только после этого сообщить, что сайт полностью опубликован.

## Граница доступа

ChatGPT технического специалиста:
- работает с GitHub;
- не входит вручную в REG.RU;
- не входит в Selectel;
- не получает пароль REG.RU, API-ключ REG.RU, пароль Selectel или root-доступ к VPS;
- не редактирует DNS, Nginx или SSL вручную;
- не придумывает собственный способ публикации.

DNS, Selectel, Nginx и SSL должны выполняться отдельной утверждённой автоматикой.

Пока production-автоматика не подключена, разрешено:
- собрать сайт;
- опубликовать и проверить GitHub Pages;
- сообщить, что production-домен ещё не подключён.

Запрещено заявлять, что `*.tanem.ru` работает, если это не было фактически проверено.

## Если что-то сломалось

Не пытаться чинить инфраструктуру случайными ручными действиями.

Нужно:
1. назвать конкретный упавший этап;
2. показать конкретную ошибку;
3. не трогать уже работающую production-версию;
4. после исправления повторить стандартный pipeline.

## Финальный ответ техническому специалисту

Коротко:
- Сборка: OK / ошибка.
- Проверки: OK / ошибка.
- GitHub Pages: <реальная ссылка> / не опубликовано.
- Production: <реальная ссылка> / ещё не подключён.
- Найденные проблемы: только конкретные факты.
