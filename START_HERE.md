# START HERE — создание сайта частного мастера

Это точка входа для нового ChatGPT, который работает с клиентским репозиторием TANEM без предыдущего контекста.

Сначала прочитайте:
1. `DEPLOYMENT.md`;
2. `RULES.md`;
3. `SOURCES.md`;
4. `FACTORY.md`;
5. актуальный `main` этого шаблона.

## Что должен передать технический специалист

Обязательно:
- ссылку на клиентский GitHub-репозиторий;
- ссылку на карточку мастера.

В репозитории:
- `business.json`;
- исходные фотографии;
- логотип, если он есть.

Желаемый поддомен можно передать сразу или перед production-публикацией.

Если ссылка на репозиторий отсутствует — запросить её до начала работы. Не просить повторно данные, которые уже лежат в репозитории.

## Самый простой вход

Технический специалист может просто загрузить в корень клиентского репозитория:
- `business.json`;
- все исходные фотографии;
- логотип, если он есть.

Не требуйте от пользователя заранее раскладывать или переименовывать фотографии.

Сначала:
1. прочитайте `business.json` целиком;
2. просмотрите остальные переданные материалы;
3. подтвердите по совокупности данных, что клиент является индивидуальным мастером;
4. определите специальность и применимый preset по `RULES.md`;
5. распределите реальные изображения по ролям шаблона и подготовьте канонические имена;
6. заполните только подтверждённые данные.

Если по материалам видно, что это салон или студия с несколькими специалистами, не собирайте сайт на Master Engine: используйте актуальный `Shablon-only-for-salons`.

Если специальность не поддерживается текущим Master Engine, не имитируйте существующий preset. Отметьте, что требуется новый поддерживаемый preset.

## Совместимость с TANEM Exporter

Если в репозитории уже есть `intake/yandex/business.json`, используйте его как основной машинный источник экспортёра. `intake/yandex/assets/` содержит исходные изображения.

Поддерживаются оба варианта входа:
- `business.json` и изображения в корне;
- `intake/yandex/business.json` и `intake/yandex/assets/`.

Пользователь не должен повторно присылать данные, которые уже находятся в репозитории.

## Работа с несколькими клиентами

В одном чате можно работать с несколькими репозиториями. Обрабатывайте каждый независимо: факты и изображения одного клиента не должны попадать в другой клиентский репозиторий.

## Сборка и публикация

Дальнейшая логика, структура сайта, языки, медиа, услуги, отзывы, контакты, fallback-сценарии и проверки определяются актуальными `RULES.md`, `SOURCES.md` и `FACTORY.md`.

Публикация, проверка GitHub Pages, production-домена и финальный статус выполняются строго по `DEPLOYMENT.md`.

Не создавайте отдельные правила в клиентском репозитории поверх шаблона, если для этого нет отдельного поручения.
