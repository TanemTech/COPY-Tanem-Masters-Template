# TANEM — инструкция агенту для сайтов частных мастеров

Этот репозиторий является production-шаблоном TANEM для индивидуальных мастеров. Перед работой с клиентом сначала прочитайте `START_HERE.md`, затем `DEPLOYMENT.md`, `RULES.md`, `SOURCES.md` и `FACTORY.md`.

## Обязательный вход

Для нового клиента технический специалист передаёт:
- ссылку на клиентский GitHub-репозиторий;
- ссылку на карточку бизнеса/мастера;
- желаемый поддомен, если он уже выбран.

В самом репозитории должны находиться `business.json` и фотографии. Если ссылка на репозиторий не передана — запросить её до любых изменений.

Публикацию и финальный статус выполнять строго по `DEPLOYMENT.md`.

## Клиентские данные

Технический специалист может загрузить прямо в корень клиентского репозитория:
- `business.json`;
- исходные фотографии с любыми понятными именами;
- логотип, если он есть.

Пользователь не обязан заранее создавать папки, переименовывать фотографии или распределять их по ролям.

Агент:
1. читает `business.json` и остальные переданные материалы;
2. проверяет, что клиент действительно является частным мастером;
3. определяет поддерживаемую специальность по данным, а не по догадке;
4. анализирует изображения и готовит канонические `hero.webp`, `profile.webp`, `gallery-XX.webp` и `logo.*` по `RULES.md`;
5. заполняет только подтверждённые факты;
6. выполняет проверки шаблона перед публикацией.

Также поддерживается прежний вход через `intake/yandex/business.json` и `intake/yandex/assets/`, если такой экспорт уже находится в клиентском репозитории.

Если одновременно присутствуют два источника и они противоречат друг другу, не объединяйте конфликтующие значения молча. Прямое указание пользователя имеет приоритет; неразрешимый конфликт кратко обозначьте.

## Несколько репозиториев в одном чате

Можно работать сразу с несколькими клиентскими репозиториями. Каждый репозиторий является отдельным клиентским контекстом. Не переносите между ними клиентские данные, фотографии или ссылки без прямого указания пользователя.

## Граница изменений

Для обычного клиентского сайта следуйте текущему Master Engine и его правилам. Не переделывайте общую механику ради одного клиента. Изменение самого шаблона выполняется только по отдельной задаче и с предусмотренными regression-проверками.
